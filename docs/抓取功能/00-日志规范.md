# 运行日志规范

## 为什么较真这个

这个项目已经吃过两次"没有日志"的亏（见 `docs/上机调试问题汇总.md`）：

- **C5**：`killall.sh` 的复查表全是 `[OK]`，但 roscore 其实压根没起来 ——
  空的 `pgrep` 有两种可能：**杀干净了**，或者**根本没东西起来**。
- **B1**：日志里 `STARTING ... at 30 FPS` 后面紧跟 `VIDIOC_STREAMON error 5`，
  当时盯着"30 FPS"调了半天帧率，真正的判据是**下一行的 EIO**。

⇒ 结论：**日志要留"当时到底看到了什么"，不要只留"我认为它好使"。**
格式不统一、时间不明、缺上下文，等于没留。

---

## 命名

```
YYYY-MM-DD_会话NN_一句话内容.md          # 人读的（结论 + 关键输出）
YYYY-MM-DD_会话NN_原始输出.log           # 机器吐的（整屏 tee 出来的）
```

例子：`2026-10-25_会话01_通读与离线复算.md`

---

## 每次上机必留的 5 行头

不管跑什么，日志开头先写这 5 行：

```markdown
- 时间：2026-10-25 21:10（车上的时间，不是电脑时间）
- 起点状态：./killall.sh 已跑 / ls -l /dev/ttyUSB* = ____
- 本次目标：只验 G1（相机话题），不动机械臂
- 跑了什么：（命令原文）
- 结论：/yolov8_detections 有数据 ✅；或 无数据 ❌（附证据行）
```

**理由**：一周后回看，"当时的 `/dev/ttyUSB*` 是哪三个"这种信息，比结论还值钱。
（C7 那次就是因为没记"设备在不在"，白查了两轮。）

---

## 原始输出怎么留

```bash
# 在车上简单粗暴地存一份到 U 盘（跟着车走）：
mkdir -p /media/abot/999/abot/_运行日志
./7-grasp-check.sh 2>&1 | tee /media/abot/999/abot/_运行日志/$(date +%Y%m%d-%H%M)-grasp-check.log
```

回到 Windows 后，把这个 `.log` 拖进本文件夹，改成上面的命名。

> `_运行日志/` 是**改动范围之外**的目录（不影响任何 ROS 包），
> 放 U 盘上是因为车上唯一的持久介质就是它。

## 一份合格日志长什么样（范例）

```markdown
# 2026-10-26 会话02 · 只修 G1，验 YOLO

## 头
- 时间：2026-10-26 15:02
- 起点：./killall.sh 跑过；/dev/ttyUSB* = ttyUSB0 ttyUSB1 ttyUSB2；/dev/arm 不存在
- 目标：只验相机话题，不碰机械臂

## 改了什么
- src/yolov8_ros/launch/multi_yolo.launch 加了
  <remap from="/usb_cam/image_raw" to="/usb_cam2/image_raw"/>
- 备份：备份/multi_yolo.launch.20261026.bak

## 跑了什么 + 看到什么
$ rostopic hz /usb_cam2/image_raw
average rate: 24.61                     ← 相机在发 ✅
$ rostopic hz /yolov8_detections
average rate: 3.12                      ← YOLO 有输出了 ✅ （改之前是 0）
$ rostopic echo -n1 /yolov8_detections
class_name: "bottle"  confidence: 0.61  x1: 210.3 ...   ← 注意：不是 car/clock/person！

## 结论
- G1 关闭 ✅
- 但撞上了 G5：桌上的瓶子被认成 "bottle"（COCO 类里有），
  而 grab.py 只认 car/clock/person ⇒ 还是要改类别策略
- 下一步：确认「按中心最近的框抓」这个方案（方案 c）

## 附
- 原始输出：2026-10-26_会话02_原始输出.log
```

## 反面例子（不要写这种）

```
今天试了抓取，能跑了
```
—— 什么车、什么设备、改了没有、跑到哪一步、抓到了没有，全没有。等于没写。
