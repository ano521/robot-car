# 零基础上机操作 · 第一次只验设备和模板

日期：2026-10-26

这份文档把第一次上机拆成很短、能照着敲的步骤。

> **本次暂停点：只做到“模板识别 + 确认哪台相机对桌面”，不要动机械臂。**
>
> 跑完本文第 3 节后把结果告诉 AI；确认无误后再进入夹爪 PWM、臂长和手眼标定。

---

## 1. 先认识界面和规则

- 车上的 Ubuntu 桌面打开终端：按 `Ctrl+Alt+T`。
- 命令输入后按回车。
- 想停止正在运行的程序：在对应终端按一次 `Ctrl+C`。
- 出现 `输 YES:` 时，只有确认安全才输入大写 `YES`。
- 机械臂第一次动之前，必须有一个人始终在电源/急停旁边。
- 本次所有识别命令都带 `dry`，不会发机械臂动作。

每次新开终端后，先进入工作区：

```bash
cd /media/abot/999/abot
```

---

## 2. 第一次只读体检

在车上终端依次输入：

```bash
cd /media/abot/999/abot
bash -n 7-grasp-check.sh
./killall.sh
./7-grasp-check.sh
```

`bash -n` 没有任何输出是正常。

`./killall.sh` 跑完后，看 `/dev/arm` 是否报告已清理。

`./7-grasp-check.sh` 重点看这些行：

| 检查项 | 应该看到 |
|---|---|
| `/dev/arm` | `[OK] ... /dev/arm -> ...（真实存在）` |
| `ttyUSB` | `ttyUSB0`、`ttyUSB1`、`ttyUSB2` 都在 |
| 机械臂串口权限 | `在 dialout 组里` |
| 相机设备 | `/dev/video0` 和 `/dev/video2` 都存在 |
| Python 依赖 | `serial`、`rospy`、`cv2`、`numpy`、`ultralytics` 都是 `[OK]` |
| 模板 | `9 张水果模板齐全` |
| `find_object_2d` | `find_object_2d 包可解析` |
| 代价地图 | 没启动 ROS 时会跳过；不是故障 |

出现下面任一情况就停止，不要继续：

- `/dev/arm` 是 `[!!]`
- `/dev/video0` 或 `/dev/video2` 是 `[!!]`
- 水果模板不是 `9/9`
- `serial`、`rospy`、`cv2` 有 `[!!]`

把出现 `[!!]` 的那几行告诉 AI。

## 3. 验模板识别和相机

### 3.1 先试 `video0`

在第一个终端输入：

```bash
cd /media/abot/999/abot
./ai.sh v0 gui dry
```

预期：

- 出现 Find-Object 窗口。
- 窗口里应有摄像头画面。
- 日志应提到加载 `object_task` 和提取模板特征。
- 日志中文有乱码不要紧，`[ERROR]` 和 `No objects loaded` 要紧。

另开一个终端，输入：

```bash
cd /media/abot/999/abot
source ros-env.sh
rostopic echo /ai_locate/ids
```

然后把水果图片/物块**一次只放一个**到镜头前。

编号对照：

| id | 水果 | id | 水果 |
|---|---|---|---|
| 1 | 火龙果 | 6 | 山竹 |
| 2 | 梨 | 7 | 西瓜 |
| 3 | 榴莲 | 8 | 香蕉 |
| 4 | 苹果 | 9 | 红枣 |
| 5 | 葡萄 |  |  |

终端里出现类似下面一行，就说明该模板被识别：

```text
data: [4]
```

`data: []` 表示这一帧没识别到，不一定代表故障。

重点测试：

- 苹果：应显示 `4`
- 红枣：应显示 `9`
- 两者尤其容易串号

## 4. 下一阶段预告（现在不要做）

模板和相机确认后，才按下面顺序继续：

1. 用 `a.py` 只动 5 号夹爪，确定“张开”和“夹住”两个 PWM。
2. 用尺子量底盘面到 2 号舵机中心轴的距离，确定 `l0`。
3. 用 `c.py click` 和 `a.py g x y z` 做 6~9 点手眼标定。
4. RMS ≤ 10 mm 后，先跑 `grasp_once` 的 `dry_run`。
5. 最后才允许真抓一次。

机械臂串口同一时间只能有一个程序打开。运行 `a.py` 前一定先停掉 `ai.sh`，并跑：

```bash
./killall.sh
```
