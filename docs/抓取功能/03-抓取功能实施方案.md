## 阶段 1 · 只修 G1（不动机械臂）

**目标**：让 YOLO 真的有图可看。这是**唯一一个"纯软件、零风险、收益最大"的改动**。

**改动（1 行，改 launch 不改 py）**
`src/yolov8_ros/launch/multi_yolo.launch`
```xml
<launch>
  <node name="yolov8_ros_node" pkg="yolov8_ros" type="multi_yolo.py" output="screen">
    <remap from="/usb_cam/image_raw" to="/usb_cam2/image_raw"/>
  </node>
  <include file="$(find yolov8_ros)/launch/usb_cam.launch"/>
</launch>
```
> 为什么改 launch 不改 `multi_yolo.py`：`sam`、`track`、`region_counter`、
> `vl_locate/server.py` 也都订阅 `/usb_cam/image_raw`，那是跟 `cam_track`(video0) 配套的。
> 动 py 会把它们一起改坏，动这个 launch 只影响这一个节点。

**验收（量化）**
```bash
./grasp.sh                       # 或只起 multi_yolo：roslaunch yolov8_ros multi_yolo.launch
# 另开终端
source /media/abot/999/abot/ros-env.sh
rostopic hz /usb_cam2/image_raw          # 应 ≈ 25 Hz
rostopic hz /yolov8_detections           # 桌上放东西时应有数据
rostopic echo /yolov8_detections         # 看 class_name 到底是什么
```
- 出数据 → **G1 关闭**，进阶段 2。
- 仍旧没数据 → 分两种：图到了但没检测（类别问题/物体太小/`conf=0.25` 太高），
  还是图压根没到（`rostopic hz /usb_cam2/image_raw` 为 0）。**这两种修法完全不同，别混。**

**顺带把 G5 定下来**：在这个阶段就知道我们桌上的东西 YOLO 认成什么类。
用 `rosrun image_view image_view image:=/usb_cam2/image_raw` 看画面 + 看日志里的 `Class: ...`。
如果认不出来（COCO 里没有），就要改策略 —— 见"待你决策的第 2 个问题"。

## 阶段 2 · 单舵机微动（第一次让机械臂动）

**目标**：在**最小动作**下确认六路舵机都能动、方向对、`/dev/arm` 真的通，
并现场定下 G9（夹爪 PWM）和 G10（臂长）。

**为什么不用 `grab.py`**：它一上来就是"多舵机联动 + 逆运动学 + 视觉"，三个未知数一起动。
用 `keyboard_grasp.launch` + `rqt_reconfigure` 一次只动一个量，出问题立刻能停。

**前置改动（两处小改，都无害）**
1. `WCXC_UartServer.py`：端口可覆盖
   ```python
   port=os.environ.get('ABOT_ARM_PORT', '/dev/arm'),
   ```
2. `7-grasp-check.sh` 的 `--probe` 用来确认"串口通"。

**步骤（顺序不能换）**
1. **串口通不通**（不发舵机指令）：`./7-grasp-check.sh --probe`
2. **舵机在不在**：手扶住机械臂（防抽动），发 `#000PRAD!` 读 0 号舵机角度
   —— 这个动作只是**读**，不动。
3. **单舵机 ±60 tick**：`#000P1560T1000!` 再 `#000P1440T1000!`。
   60 tick ≈ 8°，幅度很小。看方向、听有没异响、看有没有卡涩。
4. 逐个把 0/1/2/3/4/5 号过一遍，**记下每个舵机的"中位"和"方向"**。
5. **夹爪行程**：`#005P1200T1000!` → 记姿态；`#005P1500T1000!` → 记；`#005P1800T1000!` → 记。
   找到"张到最大"和"夹住木块"两个值，**填进日志**。

**闸门**
- 六个舵机都能单动、方向正确、无异响、夹爪能开能合 → 进阶段 3。
- 有任何一路不动/发热/异响 → **停**，那多半是总线接线或供电，不是代码。

> ⚠️ 这一步之后 `/dev/arm` 就"有属主"了。**同一时刻只能有一个进程打开它**
> （`grasp.sh` 同时起 `grab.py` + `put.py` 是错的，见断点 G2）。

## 阶段 3 · 我们自己的标定（G6 / G7 / G8）

**目标**：把厂商那 4 个点换成**我们自己机位**的映射。这是"抓得准"的唯一来源。

**做法（推荐：直接在像素 ↔ 舵机层标，绕开 mm 这一层）**
1. 桌面上画/贴 9 个标记点（3×3，间距 8~10 cm），落在相机视野中央区域。
2. 相机固定、车不动，用 `image_view` 读出 9 个点的像素坐标 `(u,v)`。
3. 手动（`keyboard_grasp` + `rqt_reconfigure`）把臂**用眼看对准**每个点，
   记下能让爪子压住该点的 `(kms_x, kms_y)`（该界面直接给 mm 坐标）。
4. 拟合一个仿射/单应：`(u,v) → (x,y)`，用 6 个点拟合、3 个点验残差。
5. 残差 ≤ 10 mm 才算过。把系数写进 `config/grasp_calib.yaml`。

**为什么不用原来的 4 点线性插值**：它是 2 点/轴的一维插值，
既不校正旋转也不校正畸变（断点 G7 已经量化出 3~6 cm 的分歧）。
仿射 / 单应只是多几个乘加，代码量差不多，精度差一个量级。

**闸门**：9 点残差 ≤ 10 mm → 进阶段 4。

## 阶段 4 · 单次抓取（不含导航）

**目标**：`放目标 → 检测 → 臂过去 → 合爪 → 抬起 → 说"成了没有"`，**一次**。

**新写一个小工具**（不改 `grab.py`，先并行验证）：
`src/yolov8_ros/script/grasp_once.py`
- 参数：`~target_class`（可为空 = 取画面中心最近的框）、`~gripper_open`/`~gripper_close`、
  `~dry_run`（**只算不发**）、`~max_offset_px`（越界放弃阈值）
- 流程：取一帧 → 选目标 → 范围检查（G8）→ 逆运动学 → 下发 → `sleep` 按 `T` 参数自适应
  （不是写死 2 秒，见 G13）→ 合爪 → 抬 → **回读夹爪角度判定抓没抓到**（G3）→ 打印结论
- `dry_run` 必须能离线跑：不连相机就用固定像素，不连串口就打印 PWM。

**验收（量化）**
- `dry_run` 打印出的 PWM 与 `02-离线逆运动学复算.md` 的基准值一致（说明复算没白做）。
- 真跑：同一目标 **连续 10 次，抓中 ≥ 8 次**。
- 每次失败都要能说清是哪一类：没检测到 / 越界放弃 / 臂到了但没夹住 / 夹住了但抬臂掉。

**闸门**：≥ 8/10 → 进阶段 5。

## 阶段 6 · 接回 `nav.py`

到这一步才谈"按 1 跑全程"。需要改的：
1. `nav.py` 的 6 处 `while True` 加超时（G4）—— **必须**，否则任何一环坏了都是静默卡死。
2. 抓取节点改成**唯一属主**（G2 第二层）：`grab.py` + `put.py` 合成一个进程，
   或者抽一个 `/arm/*` 服务节点。
3. `end()` 盲退（G14）：至少要加"后退前查一次正后方 0.5 m 无人无物"。
4. 类别序列（G5）：改成可配参数。

**验收**：3 个货架 × 3 轮全过，且中途**故意制造一次失败**（把物体拿走），
确认它能报错、跳过、继续，而不是卡死。

## 安全红线（每次动臂前读一遍）

1. 人**不在臂展范围内**（臂长 100+105+75+185 ≈ 46 cm，加底盘高度，实际扫掠半径按 60 cm 算）。
2. 急停/电源开关**在手上**，不是"在旁边桌上"。
3. 第一次试某个动作，**手扶着臂**（限速 + 手扶能立刻止住）。
4. 单次动作幅度从小到大：60 tick → 150 tick → 300 tick，不要一上来就整段动作。
5. **不要**为了"让它动起来"去改 `move_base` 的代价地图参数（D9 那个洞）。
6. 车内 `/etc`、`/home/abot` 一个字不改（udev 别名没有就环境变量绕，见阶段 0）。
7. 抓取位背后留 **≥ 0.5 m**（G14 盲退 0.27 m）。
