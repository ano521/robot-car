## 二、为什么新写，而不是在 `grab.py` 上打补丁

`grab.py` 的问题不是"缺一行"，而是结构性的（详见 `01-抓取链路通读与断点清单.md`）：

| 断点 | 在 grab.py 里的样子 | 挤进去改的代价 |
|---|---|---|
| G3 | `success` 在最后一步**无条件**置真 | 要改成"夹爪回读 + 视觉确认"，得动它的状态机 |
| G5 | `label=["car","clock","person"]` + `i` 只在成功时 +1 | 改类别等于重写触发逻辑 |
| G7 | 同一像素算两遍（`kms_x` 和 `X_mc`），云台用前者、臂用后者 | 要统一就必须重排整段 |
| G8 | `np.interp` 越界静默钳位 | 得在调用点前后都加检查 |
| G17 | 8 秒去抖会把重试静默吞掉 | 得推翻它的时间闸 |

`grab.py` 251 行、20 个全局变量、多线程共享状态。**在它上面动这五处，比新写更容易出错。**
新文件里这些是"天生就对的"：越界拒绝、失败能说出是哪一环、不按类别序列、不断言成功。

## 三、怎么跑（上机）

### 第 0 步（必做）：先看设备在不在

```bash
cd /media/abot/999/abot
./killall.sh
./7-grasp-check.sh 2>&1 | tee ~/grasp-check-$(date +%Y%m%d-%H%M).log
```

**看第 7 节的结论**，三项全 `[OK]` 再往下。

### 第 1 步：空跑（不动机械臂）

```bash
roslaunch yolov8_ros grasp_once.launch dry_run:=true
# 另开终端
source /media/abot/999/abot/ros-env.sh
rosservice call /grasp_once/trigger
```

**它做的事**：等一帧检测 → 选目标 → 算像素→机械臂→PWM → **打印**四步指令，不发串口、不置 `/success`。

**要看的**：
- 有没有 `选中目标：xxx conf=... 中心=(u,v)`
- 有没有 `规划：像素(u,v) -> 机械臂(x,y,z) alpha=... pwm=[...]`
- 打印出来的 4 条指令是否合理（PWM 在 500~2500，`alpha` 在 -12 ~ -75）

**这一步就能把 90% 的问题挡在臂动之前。**
如果这里就失败，`status` 会明确告诉你是哪一环：
`no_detection`（G1 没修好/没目标）、`no_target`（类别/面积不满足）、
`plan_failed` + `stage`（`pixel_range` / `arm_range` / `ik`）。

### 第 2 步：真抓一次（人必须站在电源旁）

```bash
roslaunch yolov8_ros grasp_once.launch
# 另开终端
source /media/abot/999/abot/ros-env.sh
rosservice call /grasp_once/trigger
```

**节点启动时会先检查**有没有 `grab.py`/`put.py` 还在跑 —— 有就拒绝启动（串口只能一个属主，G2）。

**它会依次**：张爪 → 伸到目标 → 合爪 → 抬起，每步之间按 `gripper_time`/`move_time` + `settle` 等。

**第一次跑务必**：
1. 把 `grasp_params.yaml` 里的 `move_time` 调大（比如 3000），慢一点看得清；
2. 手扶住机械臂底座，随时能按住；
3. **先只发一次**，不要连发。

### 第 3 步：标定（决定"抓得准不准"）

```bash
# 相机的画面里点一个标记点 -> 打印像素
rosrun yolov8_ros grasp_calib.py --click

# 用手动方式把爪子移到那个点上方，把当时的机械臂坐标记下来（keyboard_grasp 的 rqt_reconfigure）
rosrun yolov8_ros grasp_calib.py --add u v x y

# 凑够 6~9 个点后拟合
rosrun yolov8_ros grasp_calib.py --list      # 先看这批点的整体残差
rosrun yolov8_ros grasp_calib.py --fit --save
```

**验收**：`--fit` 打印的 `RMS` **≤ 10 mm** 才 `--save`。
超过就是点没对准 / 相机动过 / 臂长参数不对，**别硬存**。

标定文件 `config/grasp_calib.json` 生效后，启动日志会从
"回落到【厂商的 4 点插值】" 变成 "仿射 N 点，rms=X mm"。

## 五、上机时最可能撞上的三件事（提前说）

1. **`/grasp_once/trigger` 报 service not available**
   → 节点没起来。看那个标签页的第一屏：大概率是 `/dev/arm` 打不开（G2）。
   临时绕法：`export ABOT_ARM_PORT=/dev/ttyUSB2` 再起。

2. **`no_detection`**
   → 相机或 YOLO 那环还没通。先 `rostopic hz /yolov8_detections`。
   如果 0：`./7-grasp-check.sh` 第 4 节看话题对没对上（G1 改完应该对上了，
   没对上说明这个 remap 不是真正的修法，回来告诉我）。

3. **`plan_failed / pixel_range`**
   → 目标出现在标定框外（画面边缘）。这是**正确行为**（拒绝钳位），
   要么把车停得更正，要么先做标定把框扩大。
