### B. 相机

#### B1 · RViz 里 `Image: No Image`，没有画面 —— **已查清，不是设备号问题**

**2026-10-10 22:0x 实测（`v4l2-ctl --list-devices`）：车上有两台 USB 摄像头，不是一台。**

```
HD USB Camera      (usb-3610000.xhci-2.1)  →  /dev/video0, /dev/video1
Integrated Webcam_HD (usb-3610000.xhci-2.3) →  /dev/video2, /dev/video3
```

| 设备号 | 名字 | 物理设备 |
|---|---|---|
| `/dev/video0` | HD USB Camera | 摄像头 **A**（USB 口 2.1） |
| `/dev/video1` | HD USB Camera | 同上，**A 的第二个节点** |
| `/dev/video2` | Integrated Webcam_HD | 摄像头 **B**（USB 口 2.3） |
| `/dev/video3` | Integrated Webcam_HD | 同上，**B 的第二个节点** |

**关键结论：摄像头每个会出两个 `videoN` 节点，第二个通常是元数据通道，不能当普通摄像头打开。
所以真正可用的是 `/dev/video0` 和 `/dev/video2`。**

⇒ `cam_track` 用 `video0`、`yolov8_ros` 用 `video2`，**两边其实都对**——它们指的是两台不同的相机。
**原先"设备号不一致是 bug"的判断（D5）作废。**

- **B1 的真正原因待定**：RViz 里 `Image: No Image` 可能是
  (a) `3-amcl_test.sh` 起的 `usb_cam` 节点话题名与 RViz 里配的 `Image Topic` 不匹配；
  (b) 该相机没被正确打开（被另一进程占用）；
  (c) RViz 配置里压根没设 topic。**下一步：`rostopic list` 找 `/usb_cam/image_raw` 是否存在。**
- **遗留问题**：还不知道 A / B 哪一台是机器人真正用来做视觉的那台（哪台拍得到桌面/机械臂前方）。需实拍确认。
