**✅ C5 已经在启动脚本里修好了（2026-10-12）—— 正常情况你什么都不用做**

这台机器环境里预置了 `ROS_HOSTNAME=172.20.10.2` 和
`ROS_MASTER_URI=http://172.20.10.2:11311` —— 那是**旧手机热点**的网段。
机器真实 IP 一变，**`roscore` 就连不上自己、启动即退出**，症状是
`rosnode list` **无限卡住**（不报错，干等）、`ps aux | grep rosmaster` 为空。

四个启动脚本（`1-gmapping.sh` / `3-amcl_test.sh` / `4-test.sh` / `grasp.sh`）
现在开头都自己 `export` 了正确值，**直接 `./3-amcl_test.sh` 就行，不用先手工导**。

**★ 但脚本救不了你自己手敲的命令。** 你那个**交互式终端**里的
`ROS_MASTER_URI` 仍然是 `http://172.20.10.2:11311`（14:45 实测 `echo $ROS_HOSTNAME`
输出还是 `172.20.10.2`）—— 所以**在普通终端里手敲 `rosnode list`、`rostopic list`、
`rosrun map_server map_saver` 这些，照样会连到那个死 IP、照样卡住。**

⇒ **每开一个新终端，敲第一条 ROS 命令之前，先 source 一下**：

```bash
hostname -I                              # 先看真实 IP（现在是 10.128.202.88）
source /media/abot/999/abot/ros-env.sh   # ＝ export ROS_HOSTNAME=localhost
                                         # + export ROS_MASTER_URI=http://localhost:11311
```

> 这条陈旧变量是从哪来的还没查清（`.bashrc`？`/etc/profile.d/`？）——
> `grep -rn "172\.20\.10\.2" ~/.bashrc ~/.profile /etc/profile.d/ 2>/dev/null`。
> 即便查到在 `.bashrc` 里也是**车内**，不改；靠上面这句 `source` 覆盖即可。

选 `localhost` 而非动态 IP：全部节点都跑在本机，且热点重连后 IP 会变，写死最稳。

**万一还是卡住**：先 `echo $ROS_HOSTNAME $ROS_MASTER_URI` 确认是 `localhost`；
再去**第一个标签页**看有没有 `RLException: Unable to contact my own server`。

**收工时永远记得**：改动要 **U 盘和 D 盘仓库两边都落**（`E:\abot` ↔ `D:\Program Files\robot car\abot`）。

## 第 2 步 · 验证重写后的 `killall.sh` 真能杀干净（D10 / C3）

**目的**：C3"雷达起不来"的根因是残留 `rplidarNode` 占着 `/dev/ttyUSB0`，
而旧版 `killall.sh` 杀不干净。新版必须证明有效，否则后面每一步都不可信。

> ⚠️ **这一步必须分两半做：先证明东西"真的起来了"，再证明"真的被杀干净了"。**
> 2026-10-12 就栽在只做了后半截 —— 当时 roscore 因为 C5 压根没起来，
> `pgrep` 当然是空的，却被记成"验证通过"。**空的 pgrep 有两种可能，
> 一种是杀干净了，另一种是根本没东西起来**，必须先排除后者。

**（1）先启动，并确认真的起来了**

```bash
./1-gmapping.sh
sleep 15

rosnode list                 # ← C5 修好的直接证据：这里必须能列出节点，不能卡住
pgrep -a -f roslaunch        # ← 必须有输出（应有 3 条：bringup / gmapping / view_mapping）
pgrep -a -f rplidar          # ← 必须有输出（rplidarNode 在跑）
```

`rosnode list` **一卡住就停**（Ctrl-C）—— 说明 C5 没生效，先 `echo $ROS_HOSTNAME`
确认是 `localhost`，再回去看第 0 节的说明。**这四条没都对，就不要往下做。**

**（2）再杀，然后确认杀干净**

```bash
./killall.sh

pgrep -a -f rplidar          # 现在必须无输出
pgrep -a -f roslaunch        # 现在必须无输出
```

**不对怎么办**：手工补刀（已实测有效）：

```bash
pkill -9 -f 'roslaunch'
pkill -9 -f 'rosrun'
pkill -9 -f '/opt/ros/noetic/lib'                    # ROS 系统自带节点
pkill -9 -f '/media/abot/999/abot/devel/lib/'        # ★ 工作区编译的节点（abot_driver 在这）
pkill -9 -f '/media/abot/999/abot/src/'              # ★ 源码跑的 python 节点
```

> ⚠️ **2026-10-12 14:45 实测踩到的坑**：只杀前三条时，`abot_driver`
> （`/media/abot/999/abot/devel/lib/abot_bringup/abot_driver`）**每次都活下来** ——
> 它不在 `/opt/ros/noetic/lib` 下。2026-10-12 那版 `killall.sh` 已把第 4、5 条补进去
> （另加 `fuser -k` 串口兜底），但**你手上 U 盘里那份还是旧的**，所以要手敲这两条补上。

**然后重点看第 4 行 `[OK] abot_driver 已清理`** —— 这一行才是 D10 修复是否真正完成的判据。

## 第 3 步 · 导航栈回归 + D9 避障验证 ⭐ 最优先

**目的**：确认干净启动下导航栈完整；更重要的是确认 `pub_point.py`
不再关掉避障（原行为会让路径穿墙，而 `3-amcl_test.sh` 默认就启动它）。

> ⚠️ **先做 C7 的 30 秒前置检查**（2026-10-12 下午新增）。串口是死的，这一步的结论全是废的：
>
> ```bash
> ls -l /dev/ttyUSB*                 # 要看到 ttyUSB0/1/2
> ls /sys/bus/usb-serial/devices/    # 不能是空的（空 = 驱动没绑上）
> ```
>
> - **`/dev/ttyUSB*` 不存在** ⇒ 悬空软链接坑：`/dev/abot_driver -> ttyUSB1` 看着正常，
>   其实 `ttyUSB1` 没了，`ls -l` **看不出来**。
> - 取证：`dmesg | grep -iE "ttyUSB|cp210x|ch341|brltty" | tail -40`、
>   `dpkg -l | grep -i brltty`（brltty 抢串口是 Ubuntu 22.04 的常见坑，见 C7）
> - **设备不在** → 最省事的一招：`sudo reboot`，起来再验一次。
> - **设备在、但还在刷 `read err 0`** → 不是设备问题，是**老进程攥着已 hangup 的旧 fd**
>   （2026-10-12 实测：适配器掉线又回来，节点重建了，老进程不会自愈）⇒
>   **`kill -9` 掉再重启即可**，不用重启机器。
> - ⚠️ `sudo apt remove brltty` 属于**车内系统改动**，超出"只动 U 盘"的范围，**动手前先问**。
>   （brltty 这次并没有抢串口——真抢了 `/dev/ttyUSB*` 根本不会出现。先别动它。）

```bash
./killall.sh
./3-amcl_test.sh

rosnode list | grep -E "amcl|map_server|move_base|rplidarNode"
```

**期望**：`/amcl`、`/map_server`、`/move_base`、`/rplidarNode` **四个都在**。

**D9 的关键验证（别跳过）**：在 RViz 里用 `2D Nav Goal` 给一个目标点，观察红色 `Full Plan`：

- ✅ 路径**绕开**障碍物、不贴墙 → 修复生效
- ❌ 路径紧紧贴着墙甚至穿过去 → 那三行 `enabled: 0` 还在起作用，回去查
  `src/robot_slam/scripts/pub_point.py` 第 116–118 行

**不对怎么办**：
- 缺 `/map_server` → 看第 4 节 yaml 的 `image` 指向（C2）
- 缺 `/rplidarNode` → **先按上面的 C7 检查串口设备在不在**；设备都在、串口也没人占，
  再回第 2 步查残留进程（C3）
- amcl 报 `No laser scan received` → 同上，雷达没起来
- 底盘不动、屏幕上 `abot_driver` 刷 `read err 0` → **C7**（不是"读坏了"，
  是串口已经 hangup；`read()` 返回 0 = EOF），查 `/dev/ttyUSB*`

**键盘对照**（`teleop_twist_keyboard`）：

```
   m    ,    .
```

`i` 前进 · `,` 后退 · `j` 左转 · `l` 右转 · `k` 停 · `q`/`z` 调速

- `view_gmapping.rviz` 已配好：Fixed Frame = `map`，LaserScan = `/scan_filtered`，Map = `/map`，**不用手动打勾**
- `gmapping.launch.xml` 里 `xmin/ymin/xmax/ymax` 只有 ±1.0 m 方框，**不用改** ——
  那只是初始尺寸，gmapping 会自己扩图（厂商地图是 14.7 m × 14.7 m）

**收尾**：回到 Windows 后把 `my_home.{pgm,yaml}` 同步到 D 盘仓库。
