# 视觉识别与视觉跟踪

对应厂商手册：第 2 章（PDF 第 12-23 页）和第 3 章（PDF 第 24-32 页）。

## 1. 已实现的能力

### 模板匹配识别

- 使用工作区内已有的 `find_object_2d` 和 `abot_find/object/` 模板目录。
- 发布识别框、目标 ID 和图像中心坐标。
- 调试图发到 `/image_with_objects`。
- 可由摄像头直接计算目标中心的横向偏差。

### AR 标签识别

- 使用工作区内的 `ar_track_alvar`。
- 默认读取 `/usb_cam/image_raw` 和 `/usb_cam/camera_info`。
- 发布 `/ar_pose_marker`，可与摄像头话题解耦配置。
- 不再使用 PR2 示例中的 `/kinect_head/...` 话题和 `/torso_lift_link` 坐标系。

### 视觉跟踪

两类目标共用 `vision_tracker.py`：

- 模板匹配：根据目标中心相对图像中心的像素偏差控制旋转。
- AR 标签：根据 `atan2(marker.x, marker.z)` 计算目标方位角。
- 只发布角速度，不发布线速度。
- 有中心死区、低通滤波、角速度限幅和目标丢失超时停车。
- 运动默认关闭；只有显式设置 `enable_motion:=true` 才可能输出非零 `/cmd_vel`。
- 状态和误差可用于绘图：
  - `/vision_tracking/target`
  - `/vision_tracking/error`
  - `/vision_tracking/status`

## 6. 模板视觉跟踪

第一次必须保持运动关闭，只观察识别和状态：

```bash
roslaunch robot_slam vision_template_track.launch \
  start_camera:=true \
  target_object_id:=-1
```

确认目标 ID 后，把 `target_object_id` 改为实际 ID。默认 `-1` 表示选择画面中面积最大的目标。

场地清空、机器人周围留足空间，再显式开启运动：

```bash
roslaunch robot_slam vision_template_track.launch \
  start_camera:=true \
  target_object_id:=-1 \
  enable_motion:=true \
  max_angular_speed:=0.20
```

运行时可临时关闭运动：

```bash
rosparam set /vision_tracker/enable_motion false
```

## 7. AR 标签视觉跟踪

先生成 ID 为 0 的标签；打印时要保持实际比例：

```bash
rosrun ar_track_alvar createMarker 0
```

量出标签黑色边框的边长。`marker_size` 使用厘米，默认 `4.4`。

先只验证识别：

```bash
roslaunch robot_slam vision_ar_track.launch \
  start_camera:=true \
  marker_size:=4.4 \
  target_marker_id:=0
```

确认 `/ar_pose_marker` 有数据后，再开启运动：

```bash
roslaunch robot_slam vision_ar_track.launch \
  start_camera:=true \
  marker_size:=4.4 \
  target_marker_id:=0 \
  horizontal_fov_degrees:=62.0 \
  enable_motion:=true \
  max_angular_speed:=0.20
```

## 8. 调参

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `enable_motion` | `false` | 是否允许发布非零 `/cmd_vel` |
| `deadband` | `0.06` | 目标进入中心区域后停止旋转 |
| `angular_gain` | `0.8` | 归一化偏差到角速度的增益 |
| `max_angular_speed` | `0.35` | 最大角速度，单位 rad/s |
| `lost_timeout` | `0.6` | 目标消失后持续停车的时间判定 |
| `smoothing_alpha` | `0.35` | 偏差低通滤波系数 |
| `horizontal_fov_degrees` | `62.0` | AR 方位角归一化使用的相机水平视场角 |
| `use_camera_info_fov` | `true` | 有有效 `camera_info` 时自动用焦距计算水平视场角 |

先在低速度下测试。中心附近仍左右摆动时，增大 `deadband` 或降低 `angular_gain`。

## 9. 安全判据

必须同时满足以下条件才允许开启 `enable_motion`：

1. `/cmd_vel` 只有本跟踪节点在发布，`move_base` 没有运行。
2. `/scan` 正常，但视觉跟踪本身不依赖雷达避障，因此仍需人工清场。
3. 摄像头画面稳定，目标 ID 正确。
4. `max_angular_speed` 从 `0.15-0.20 rad/s` 开始。
5. 手边保留 `Ctrl-C` 或 `./killall.sh`。

## 10. 常见问题

| 现象 | 检查 |
|---|---|
| `/image_with_objects` 没图 | 相机话题是否等于启动参数；`rostopic hz` 是否大于 0 |
| 模板匹配框有、无 `/object_position` | 是否启动了 `print_objects_detected` |
| AR 有画面但无 `/ar_pose_marker` | `camera_info`、标签尺寸、标签清晰度和光照 |
| 跟踪方向相反 | 不要盲目改符号；先核对相机坐标轴和画面左右方向 |
| 原地高频摆动 | 增大 `deadband`，降低 `angular_gain` 和 `max_angular_speed` |
| 目标丢失后机器人不停 | 检查 `/vision_tracking/status` 和 `/cmd_vel`；预期状态为 `target lost` 且角速度为 0 |
