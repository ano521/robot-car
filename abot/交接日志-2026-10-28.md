### 8.2 卡在哪：`find_object_2d` 段错误

现象两种表现，同一个死因：

1. `roslaunch` 报 `process has died [pid …, exit code -11]`（SIGSEGV），崩在 `Features extraction from 9 objects` 之后 <0.5 秒。
2. 有时进程留着但已死：`rosnode info /find_object_2d` → **`Subscriptions: None`** + `ERROR: Communication with node ... failed!`；`rosnode list` 里却还在（master 的注册残留）。

后果：`/objects` **零消息**（`rostopic hz /usb_cam2/image_raw /objects` 只出相机那行）→ `ai_locate` 不发 `ids`
（它只在收到 `/objects` 后才发）→ `grasp_once` 永远等不到目标。**别去改 `ai_locate`，它是被上游饿着的。**

### 8.3 根因（已用 gdb + ldd 证实，别再猜）

`gdb -batch -ex run -ex bt --args ./devel/lib/find_object_2d/find_object_2d image:=/usb_cam2/image_raw`：

```
Thread 11 "QThread" received signal SIGSEGV
#0 cv::resize        () from /lib/aarch64-linux-gnu/libopencv_imgproc.so.4.2
#1 cv::SIFT_Impl::detectAndCompute  () at /lib/aarch64-linux-gnu/libopencv_features2d.so.4.5
#2 find_object::Feature2D::detectAndCompute   (libfind_object_2d.so)
#3 find_object::computeFeatures               (libfind_object_2d.so)
#4 find_object::ExtractFeaturesThread::run    (libfind_object_2d.so)
#5 libQt5Core.so.5 / #6 start_thread / #7 thread_start
```

`ldd ./devel/lib/find_object_2d/find_object_2d | grep opencv` ⇒ **同名库 4.2 和 4.5 同时被加载**
（`core`、`imgproc`、`features2d`、`flann`、`dnn`、`calib3d` 等都是两套）。

机理：动态链接器按"先加载者优先"解析同名符号。ROS 的 `cv_bridge` 用系统 **4.2**，先加载；
而 `libfind_object_2d.so` 是拿 Jetson 的 **4.5** 编的。于是 4.5 的 `SIFT_Impl` 调 `cv::resize`
时绑到了 4.2 的实现，传进去的却是 4.5 构造的 `_InputArray` ⇒ 越界/错位 ⇒ 段错误。

> 为什么 9 张模板不崩：模板走 `cv::imread`，全程在 4.5 内部，没有跨库对象。
> 一帧真实图像进来（经 `cv_bridge` 4.2 转换）才跨界。

**这一天里我先猜过三个原因（GUI、`pnp`、mjpeg 格式），全错。** 教训：有 backtrace 就去看 backtrace。

### 8.4 下一步（按顺序，先便宜后昂贵）

**方案 A（零重编，先试这个）**：把特征检测器从 **SIFT 换成 ORB**。
SIFT 是崩溃入口，而 ORB 的符号会解析到先加载的 4.2 实现上，与 `cv_bridge` 一致，可能直接绕开。
做法：新建/覆盖 `_ros/find_object_2d.ini`（`settings_path` 指的就是它）：

```ini
[Feature2D]
1Detector=4:Dense;Fast;GFTT;MSER;ORB;SIFT;Star;SURF;BRISK;AGAST;KAZE;AKAZE;SuperPointTorch
```

`4:` 是索引（0=Dense 1=Fast 2=GFTT 3=MSER **4=ORB** 5=SIFT …），后面那串**必须和默认列表逐字一致**
（`Settings.cpp` 会比对长度，不一致会按索引重建）。
试完看 `rostopic hz /objects` 有没有频率。

**方案 B（方案 A 不行再做）**：重编 `find_object_2d` 对齐系统 4.2：

```bash
catkin_make --pkg find_object_2d -DOpenCV_DIR=/usr/lib/aarch64-linux-gnu/cmake/opencv4
```

注意：4.2 里**没有** `cv::SIFT`（在 contrib 的 `xfeatures2d` 里），所以重编后必须配方案 A 的 ORB，
或者确认 `opencv-contrib` 装了。重编前先 `git status` 留个还原点。

**方案 C（都不行才考虑）**：`LD_PRELOAD` 把 4.5 的库提到最前，让 cv_bridge 也跑在 4.5 上。
属于把同样的混用换个方向，风险更大，仅作最后手段。

### 8.5 顺手记下的两个小债

1. **`7-grasp-check.sh` 的 dialout 判据是误报源头**：应改成直接看 `/dev/ttyUSB*` 的权限位
   （或直接 `test -r`），别再查 `groups`。今晚它让人白紧张了一次。
2. **`usb_cam.launch` 的 `pixel_format=mjpeg` + `color_format=yuv422p`** 会让 usb_cam 每帧打一行
   `[swscaler] No accelerated colorspace conversion found from yuv422p to rgb24`，把终端刷满、
   也没必要（只开一台相机时带宽充足）。跑的时候用 `./ai.sh v0 dry 2>/dev/null` 压掉；
   以后可以考虑改成 `pixel_format=yuyv` 并去掉 `color_format`（`cam_track` 在 video0 上就是这么用的）。
