## 这是什么

ABOT-M1-ATK（Jetson + ROS 1 Noetic）移动抓取机器人。厂商代码只能在他们自己的
实验室房间跑，本项目的工作是**把它改到我们自己的房间能用**。

- 车上工作区：`/media/abot/999/abot`（＝这个 U 盘）
- Windows 仓库：`D:\Program Files\robot car\abot`
- 私有仓库：`ano521/robot-car`，分支 `main`

## 硬约束（不要违反）

1. **车内 `/etc`、`/home/abot` 一个字都不改**（含 udev 规则、`.bashrc`、`profile.d`）。
   所有改动只落在工作区（U 盘）里。
2. **不要在 `/home/abot` 下建指向 U 盘的软链接。**
3. **不要在 `src/` 下建 `build`/`install`/`log`** —— 那会让 `rospack find` 解析到错误路径。
4. **工作区改动要 U 盘和 Windows 仓库两边都落**，没有自动同步。
5. **别去 `rosdep init`**（`the rosdep view is empty` 是无害告警）。

## 上机前必做

```bash
cd /media/abot/999/abot
```

### 视觉链路：C++ 那条不能用，改走 Python

`find_object_2d`（C++）在这台 Jetson 上**必崩**：进程里同时装着 OpenCV 4.2（`cv_bridge`）
和 4.5（`libfind_object_2d.so`），符号冲突 —— SIFT 崩在 `cv::resize`，换 ORB 崩在构造。

⇒ **用 `./ai.sh ... orb`**（Python 版 `template_orb.py`），它发同样的 `/objects`，
`ai_locate` / `grasp_once` 一行都不用改。已实测 25 Hz、大目标识别很准。

根治办法是重编对齐 4.2，但**不急**（见 8.4）。三条路别同时起，都占 `/usb_cam2`。

### 两个拦路虎，都在代码之外

1. **从未标定** —— `config/grasp_calib.json` 不存在，一直用厂商 4 点插值 ⇒ **臂会伸错位置**。
   **标定完成之前禁止 `dry_run=false` 抓取。** 工具已验证可用（`c.py click` / `a.py`）。
2. **小物块失焦** —— 大目标准、小物块认不出。先做距离扫描（20→80 cm）判断是"糊"还是"太小/无纹理"，
   再决定拧镜头还是加 ROI 放大。

### 环境两条新坑

- 新终端敲 ROS 命令前要 source **两个**：`devel/setup.bash`（否则 `rospack` 找不到包）
  + `ros-env.sh`（否则命令无限卡住）。`交接说明.md` 只写了后者。
- `/dev/null` 目前 `2>/dev/null` 会报权限不足，用 `2>&1 | grep -v swscaler` 代替。
